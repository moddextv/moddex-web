Every page moddex.tv can render.

Static comps of the next.js app next door — one file per page, plus the states a page can be in that a screenshot of the happy path never shows: loading, empty, opted out, banned, thrown.

They use the same class names as src/, so markup can be moved in either direction. The pages control in the bottom-right corner is on every comp and links them all together.

Redesign suggestions

Three directions live in design/suggestions/, all with the mark and the palette locked. v1 is the evolution: this design, its own rules actually enforced. v2 repositions it as a Twitch companion tool. v3 is the current front-runner: v2's structure with its own identity and a lot more air.

What is real and what is not

Every class name, colour, duration and piece of geometry is copied from the app. The data is invented: no twitch avatar is fetched, so profile pictures are tinted initial blocks, and the counts are plausible rather than current.

Where a page needs to show two states at once — a valid and an invalid field, a resolved and an unresolved donation — the second sits below a hairline rule labelled in text-primary-600. Those labels are scaffolding and have no counterpart in src/.

Three files hold the system

assets/theme.js

the palette, flattened out of what the heroui plugin generates in tailwind.config.mjs

assets/design.css

brackets, ticks, motion tokens and the self-hosted fonts — copied from src/styles/globals.css

assets/pages.js

the page registry and the switcher. add a row, write the file, nothing else to update.

Tailwind itself comes from the play cdn, so these pages want a network connection for layout. Type and badges are local.
